Hash generator (SHA family)

Compute the SHA-1, SHA-256, SHA-384 and SHA-512 fingerprints of a text, all at once.

Runs locally: your input never leaves this page.

Empty input: the values below are the hashes of an empty string.

How it works

The text is converted to UTF-8 bytes and hashed with the browser’s Web Crypto API (crypto.subtle.digest), the same implementation browsers use for HTTPS. Example: the SHA-256 of “abc” is ba7816bf…f20015ad.

A hash is not encryption

  • A hash is a one-way fingerprint: it cannot be “decrypted” or reversed. Websites that claim to reverse hashes only look up precomputed hashes of common inputs.
  • The same input always gives the same hash, and the smallest change gives a completely different one.

Which algorithm?

  • SHA-256 is the usual choice for checksums and integrity checks.
  • SHA-1 is broken for collision resistance: do not use it for security, only for compatibility (for example, older Git object IDs).
  • MD5 is not offered: browsers do not provide it in Web Crypto, and it is broken for security.
  • For storing passwords, never use a plain hash: use a slow, salted algorithm such as Argon2, scrypt or bcrypt.
