JWT decoder

See what is inside a JSON Web Token: algorithm, claims and expiry, decoded in this page only.

Runs locally: your input never leaves this page.

~/bitbench/jwt-decoder local
!
Decoding is not verification: anyone can create a token with any content. Only a signature check with the right key proves a token is authentic. Avoid pasting live production tokens into any website; this page decodes locally and sends nothing.

Decoding is not verification

A JWT has three Base64URL parts: header, payload and signature. The first two are only encoded, not encrypted: anyone can read them, and anyone can create a token with any content. Only verifying the signature with the right key (HMAC secret or public key) proves the token was issued by who you think. This tool does not verify signatures.

Handle tokens with care

  • A valid token often grants access to an account or an API. Treat it like a password.
  • Prefer tokens from development or test environments; this page processes them locally and sends nothing, but other websites may not.
  • Revoke a production token if you think it has leaked.

Dates

iat (issued at), nbf (not before) and exp (expires) are Unix timestamps in seconds. They are shown in UTC and in your local time, with whether the token is expired according to your device’s clock.

Supported tokens

Signed tokens (JWS, 3 parts, including unsigned tokens with an empty signature). Encrypted tokens (JWE, 5 parts) cannot be read without the key and are reported as such.
